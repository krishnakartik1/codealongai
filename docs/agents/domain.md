# Domain docs

Before exploring the codebase:

1. Read root `CONTEXT.md` when it exists.
2. Read relevant decisions under `docs/adr/`.
3. Proceed silently when either location does not exist.

Use the glossary’s established vocabulary in issues, specifications, tests, and
code. When terminology is missing, note the gap for domain modeling. Surface any
conflict with an existing ADR instead of silently overriding it.

This repository uses a single-context layout:

```
/
├── CONTEXT.md
├── docs/adr/
└── src/
```
